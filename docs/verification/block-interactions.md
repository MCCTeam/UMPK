## Established client behavior

| Boundary | Vanilla behavior | Implementation |
| --- | --- | --- |
| 1.8, protocol 47 | Initial swing precedes START | `BlockInteractionProfile.InitialSwingBeforeStart` |
| 1.9 and later | Initial START precedes the swing | The same profile selects the later ordering |
| Non-instant held mining | The initial click and first continuation can occur in one client tick; each continuation accumulates single-precision progress and swings | `InteractionActions.TickMiningOnLoopAsync` runs on the existing session tick before movement reporting |
| Completed survival mining | STOP precedes the last continuation swing | The action completes after both writes; acknowledgment waits remain outside the session loop |
| Creative and sufficiently fast initial breaking | START without STOP | The instant path sends one initial animation and does not invent a local world change |
| 1.21.5, protocol 770 | Instant breaking tests abilities rather than only game mode | `InstantBreakUsesAbilities` |
| 26.3, protocol 777 | Mining fatigue uses `pow(0.3, amplifier + 1)` | The profile selects this separately from the older piecewise multipliers |
| 26.3, protocol 777 | CHANGE_DESTROY_DIRECTION is inserted after START; ABORT is ordinal 2 and STOP is ordinal 3 | The profile emits native action ordinals; the packet model retains its raw wire-ordinal contract |
| Caller cancellation | Release an owned live attack with ABORT, DOWN and default sequence 0 | Cancellation is marshaled to the same owner; session teardown sends nothing into a dead connection |
| Tool or component change | Restart held mining rather than retaining previous progress | The current component comparison restarts the operation; legacy damage-equivalence rules remain to be completed |
| 1.8 teleport | Echo resolved position and rotation without a teleport ID | `SelfApplier` now sends the native position-and-look confirmation |
| 1.8 placement cursor | Convert to float before multiplying by 16; the upper face is byte 16 | `InteractionActions.LegacyCursor` |

The 1.8 source witnesses include `1.8-client-decompiled/bsu.java`, `cem.java` and `1.8.9-client-decompiled/bcy.java`. The modern witnesses include `26.3-client-decompiled/net/minecraft/client/Minecraft.java`, `client/multiplayer/MultiPlayerGameMode.java`, and the matching player, tool and player-action packet classes. Exact inspected source hashes and runtime binary hashes are recorded in `/tmp/umpk-block-mining/mining-runtime-proof.json`.

## Placement prediction in progress

`BlockInteractionDump.java` now measures native block-use inheritance, nonreplacement contracts and default-item placement inheritance on all 44 stable mapped or unobfuscated releases from 1.14.4 through 26.3, including 26.1.1 and 26.1.2. The resulting `block-interactions.json` tables cover 32 protocols. Unknown specialized item rules remain explicit. DataGen validates and emits the contracts; `JavaGameData.BlockInteractionData` exposes immutable named lookups independently of numeric server registry ordering.

The first placement prediction path covers a measured ordinary full-cube item against a passive nonreplaceable block, or a nonreplaceable block whose activation is suppressed by sneaking, with loaded air at the destination, permitted game mode, no active tracked cooldown, an unchanged component prototype and a nonintersecting player physics box. Other entities currently make this prediction unknown because their native `blocksBuilding` traits and dynamic dimensions are not yet represented. Unknown predictions retain packet-only behavior; they are unfinished acceptance work. The path does not mutate authoritative world or inventory state. Successful local placement sends use-on followed by the selected hand's swing through protocol 776. Protocol 777 keeps the predicted swing local and sends no punch packet for use.

Placement preparation and its packet group now run on the session owner. Acknowledgment waits run outside it and use the captured session lifetime. Awaiting placement from the session loop is rejected, and an ended or absent connection cannot continue an acknowledgment wait. Caller cancellation before commitment prevents the action; cancellation after commitment preserves the live packet group, including its required animation. Session cancellation still stops further writes. Seventeen focused tests cover animation timing before acknowledgment, offhand selection, occupied cells, self obstruction, spectator mode, cooldowns, pass-through items, the 26.3 boundary, the world border, session ownership and the two cancellation lifetimes. The cancellation regression first failed with a written use-on and missing swing, then passed after the packet group used the captured session token.
