`data/java/` is the part of UMPK that would survive a rewrite. It is JSON describing 49 protocol versions of Minecraft: which packet id means what, which blocks exist and what shape they collide as, which items and entities and registries and menus and command argument types the version knows, and which behavioral eras it belongs to. The C# in `src/` is a reader for it.

Calling it the canonical dataset is not marketing. When the dataset and the code disagree, the code is wrong by definition, because the dataset is what was extracted from Mojang's own server jars and the code is what somebody wrote afterwards.

## What is in a protocol directory

One directory per protocol number, named for the number. The file set varies by era:

| File | Holds |
| --- | --- |
| `packets.json` | wire id to packet identifier, per phase and flow |
| `blocks.json` | blocks and their states, with state id ranges |
| `items.json` | the item registry |
| `entities.json` | entity types and their ids |
| `registries.json` | static and synced registries |
| `components.json` | data components (1.20.5 and later) |
| `menus.json` | container and menu types |
| `argument_types.json` | Brigadier argument type registry |
| `metadata.json` | entity data serializer order |
| `metadata-keys.json` | named entity metadata keys |
| `lang.json` | vanilla's per-protocol `en_us` translation table |
| `shapes.json` | collision shapes |
| `block-shape-refs.json` | per-state references into the shape table |
| `block-push.json` | piston push reaction, unbreakable and block-entity flags |
| `features.json` | the feature axes for the era |

`block-shape-refs.json` and `block-push.json` are conditional outputs. A protocol without a `block-push.json` has no push measurement, which the generator turns into an empty table. That is not the same claim as "every block behaves normally here", and nothing in the pipeline is allowed to treat it as one.

Every file carries a `_provenance` block naming where it came from: a server data report, a decompiled class, or a human decision. When you are trying to work out how much to trust a value, that block is the first thing to read.

Alongside the per-protocol directories sit `versions.json`, the release-name catalog described in [versions and protocols](versions-and-protocols.md), and `shared/`, which holds cross-version curated tables such as block attributes, packet name aliases and the legacy item bridge.

## From JSON to compiled tables

`tools/Umpk.DataGen` reads the dataset and emits 53 `.g.cs` files into `src/Umpk.Data.Java`: one `Descriptor.g.cs` per protocol, plus catalog and shared-table outputs. With `--out-lang` it also emits the language tables into `src/Umpk.Data.Lang`. With `--protocol-out`, it emits the generated codec mirrors and per-era tables that live in `src/Umpk.Protocol.Java`. Those three outputs are one generation boundary.

A generated descriptor is deliberately dull:

```csharp
var gameVersion = new GameVersion(GameEdition.Java, "1.8.9", 47);
ProtocolFeatures features = BuildFeatures();
var builder = new ProtocolDescriptorBuilder(gameVersion, features);

PacketRegistrar.Register(builder, ProtocolPhase.Handshake, PacketFlow.Serverbound, 0x00, "minecraft:intention");
PacketRegistrar.Register(builder, ProtocolPhase.Login, PacketFlow.Clientbound, 0x00, "minecraft:login_disconnect");
```

The generated code knows wire ids and identifiers. It knows nothing about codecs and no longer carries a per-version `codecKey`. `PacketRegistrar.Register` accepts no codec key. Choosing which codec implements a packet on a given protocol happens in the hand-authored, family-local packet timelines described in [the packet pipeline](packet-pipeline.md). Keeping that split is what stops the generator from having to understand era logic and stops the codecs from being generated.

## Generated files are not edited

This is the one rule in the dataset layer that has no exceptions. Every `.g.cs` file opens with an auto-generated header and the command for its output root. For example, a Data.Java file says:

```csharp
// <auto-generated>
// Generated by Umpk.DataGen from data/java. Do not edit by hand.
// Regenerate: dotnet run --project tools/Umpk.DataGen -- generate --data data/java --out src/Umpk.Data.Java
// </auto-generated>
```

A hand edit to a generated file survives exactly until the next regeneration, and in the meantime it makes the dataset a liar. If a generated value is wrong, either the dataset is wrong or the emitter is wrong. Fix whichever it is and regenerate.

## The three commands

Run all three from the repository root.

1. Validate the dataset:

   ```bash
   dotnet run --project tools/Umpk.DataGen -- verify --data data/java
   ```

The command must print `verify: OK (49 protocols)`. Any other output is a failure.

2. Compare two protocols:

   ```bash
   dotnet run --project tools/Umpk.DataGen -- diff --data data/java 765 766
   ```

The command prints a structured difference between the two datasets. Use it to see what a version bump changed.

3. Start with no uncommitted generated-file changes. Regenerate all C# outputs and prove none changed:

   ```bash
   dotnet run --project tools/Umpk.DataGen -- generate --data data/java \
       --out src/Umpk.Data.Java --out-lang src/Umpk.Data.Lang --protocol-out src/Umpk.Protocol.Java
   git diff --exit-code -- ':(glob)src/Umpk.Data.Java/**/*.g.cs' \
       ':(glob)src/Umpk.Data.Lang/**/*.g.cs' ':(glob)src/Umpk.Protocol.Java/**/*.g.cs'
   ```

The Git command must print nothing and exit with status 0.

That comparison proves that the committed generated code is what the current dataset produces and that the emitter is deterministic. A diff means that somebody edited generated code, changed the dataset without regenerating, or introduced non-deterministic output. Investigate all three cases.

Run it after any dataset change, before you decide you are done. [Development](../contributing/development.md) puts it in the context of the full build gate, and [adding a version](../contributing/adding-a-version.md) walks the extraction path that produces new dataset files in the first place.
