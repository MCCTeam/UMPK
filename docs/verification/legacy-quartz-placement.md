## Native rules and scope

The source audit binds the registered quartz Block/ItemMultiTexture family across fifteen retained client profiles. Protocol 47 keeps its 1.8.9 profile. Each legacy dataset has one canonical quartz item at id 155; the existing slot codec carries other signed-short metadata in the Damage component. No dataset, feature axis, public API, dependency or DI lifetime changes.

Item metadata 2 chooses lines_y for up/down, lines_z for north/south and lines_x for west/east. Metadata 1 chooses chiseled. Metadata 3/4 and every other value place default quartz. Block-state decoding has a different rule: 3/4 decode fixed X/Z states. The runtime preserves the original face and positive item metadata for the server to apply the state. Its placement variants share the inherited full-unit collision box and ordinary survival rule.

The native stack constructor clamps negative metadata to zero. UMPK's received stack preserves the raw signed short and its exact incoming byte round trip; only the protocol-47 action sender projects negative quartz metadata to zero. Positive 3/4 remain unchanged on the wire. Unsupported patches, custom LegacyNbt and unrepresentable counts keep their existing unknown result. Other items retain their previous behavior.

Original controller source separates the placement precheck from Adventure permission. ItemBlock.canPlaceBlockOnSide runs before USE and calls the world placement query without checking player permission. Known obstruction therefore rejects before sending. With clear default/no-NBT quartz in Adventure, ItemBlock instead denies player permission after USE and does not swing. Protocol 47 returns boolean false; 107–340 return the native FAIL enum. The existing owner still controls activation, cooldown order, hand availability, membership, collision and session lifetime.
