# Enchantment wire-level admission

Commit `f2b2d70` validates received `enchantments` and `stored_enchantments` component levels on protocols 766–777. Native constructors admit a final last-wins map only when every surviving level is in 0–255. A later valid value for the same key can overwrite an earlier invalid value; a different key cannot. This bound is independent of the enchantment definition’s normal maximum level.

The change stays in `EnchantmentsCodecImpl.Decode`. It preserves every raw entry and its order, tracks invalid final raw holder IDs with a lazily allocated set, reads the legacy tooltip field, then rejects an invalid final map with `ProtocolViolationException`. Ordinary valid-level payloads add no allocation beyond the existing list. Encode, Hash, public models, component tables, dependencies, data and DI remain unchanged. Wire-valid zero remains separate from modern DATA-hash availability.
